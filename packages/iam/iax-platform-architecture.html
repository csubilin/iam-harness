总决策依赖关系插件布局算法暴露任务闭环方案对比实施顺序

Architecture decision · 2026-10-11

面向 AI 辅助设计的
插件与算法架构

以 Mining 项目作为业务数据主线，以 IAM 汇集几何与领域算法，以 DeepSeek Harness 承担 Agent、会话和插件装配。文档提供知识与依据；每次设计任务形成可追溯的计算、成果与修订。

独立方案内置 + 用户能力地质建模 / 储量 / 规划 / 概预算
01

总决策

核心结构

三个边界，一条业务主线

Harness 组织会话、插件、工具与任务；IAM 提供可发现、可验证的算法契约；Mining 保存项目对象、属性、几何和修订。Agent 从工作空间读取原始资料，建立 Mining 数据，之后围绕 Mining 快照完成计算和设计。

分发原则

能力与插件分开版本化

算法实现属于 C++/Python 能力包；Harness bundle 负责将能力注册为服务、工具、视图或工作流。一个算法不必对应一个 bundle。用户形成的能力先驻留工作空间，确认后可发布为可安装的插件。

交互与编排
DeepSeek HarnessAgent · 会话 · profile / bundle · 工具 · 审批 · 后台任务 · Skill
↓ 发现、调用、记录
平台服务
IAM 能力层工作空间索引 · 算法注册表 · 数据访问 · 执行桥接 · 成果与任务记录
↓ 固定快照、明确后端、候选成果
数据与计算
Mining + Drawing + GeomAlg + 用户算法对象 / 属性 / 几何 · 原生算法 · 导入器 · 用户提供者；文档保留在知识库

现有基础：仓库已有四个 Harness bundle、IAM 算法目录与 C ABI / pybind11、ViewAgent，以及 Mining 的不可变快照和修订检查提交路径。本页新增的是统一发现、用户能力注册、任务编排、知识关联和成果提升机制。

02

依赖关系图

A → B 表示 A 调用或依赖 B，不是数据流向。蓝色是本方案拟增加的服务依赖，绿色是仓库已有的插件或原生模块依赖；同一行右侧的节点分别是独立依赖。

边界约束：下层 CoreEngine、GeomAlg、Drawing、Mining、DwgFile 不依赖 IAM 或 Harness；Mining 不链接 DwgFile；Drawing 与 Mining 不因 AI 插件互相链接。IAM 算法库是否包含 Mining 后端由构建选项决定。依据：IAM 组合边界、算法目标链接、Mining 模块边界。

03

插件、包与目录布局

“类型”按插件提供的运行职责划分；“来源”按内置、工作空间、个人或团队划分。两者是独立维度。包是交付单元，bundle 是 Harness profile 使用的装配格式。

插件职责提供什么建议包界面要求
服务工作空间、Mining 项目、算法注册表、成果库、任务记录；供插件互相调用Workspace、MiningRepository、AlgorithmRegistry、ArtifactStore无
工具向 Agent 暴露受控入口，如数据导入、能力检索、运行、提交保留 Import；新增 AlgorithmBridge、MiningTools无，须可用于 headless
工作流输入要求、步骤依赖、验收规则与成果定义GeologyWorkflow、ReserveWorkflow 等独立包可选
视图预览、交互、选择和编辑反馈保留 DrawingView、MiningView有
界面品牌、项目导航、任务与成果面板保留 Brand；按需要增加项目面板有
内置

随平台发布

源码保存在 IAM/plugin/，由平台 profile 选择组合。每个 bundle 用 package.json 的 dsh.bundle.patch 指向 cordis.patch.yml；需要浏览器界面时才声明 dsh.client。

用户形成

先在工作空间，后按范围提升

源码、清单与测试保存在工作空间。需要装载的 Harness 插件经 profile 安装；复制目录本身不会自动生效。确认后可发布到个人或团队包库，并以固定版本安装。

Skill 是任务说明和知识，不是可执行插件。工作空间 Skill 应使用 Harness 已支持的 .dsh/skills/ 发现路径；文档原件及检索索引仍归工作空间管理。

  Workspace/  MiningRepository/  AlgorithmBridge/ # 建议新增的服务与工具
  Workflows/                                    # 按业务流程发布

04

算法如何暴露给 Harness

IAM 的现有 algorithms.json 是编译进 IamAlgorithms 的内置目录。用户算法需要运行时注册，不能通过追加静态 JSON 假装已经被当前二进制实现。

01 / DISCOVER

统一目录

合并内置算法与已启用的用户提供者；每条能力记录来源、版本、后端、输入输出、单位坐标、前置条件、规模上限和副作用。重名 ID 拒绝装载。

02 / SELECT

显式选择

Agent 按任务、Mining 资源类型与规模检索；执行前读取完整契约。Mesh、Facet、B-rep 的后端选择写入任务记录，不做静默替换。

03 / EXECUTE

按实现运行

内置算法复用 IAM 的 pybind11 / C ABI；用户 Python 或原生程序默认独立进程，限制资源和输出。只有受信任且确需性能的提供者才考虑进程内装载。

Harness 入口返回设计理由
algorithm_search候选能力摘要、可用后端、适用条件让 Agent 发现能力，而不是猜工具名
algorithm_describe完整参数与结果契约、限制、版本调用前可验证参数和损失边界
algorithm_run结果引用、诊断、来源、后台任务 ID避免把所有算法和大规模几何塞进工具表与会话文本
artifact_review / commit候选成果对比、编辑增量及发布修订将计算成果与 Mining 写入分开

执行数据边界：一次 Python 任务内的 Mesh/B-rep 结果可继续用原生对象串联；跨进程、跨任务只传版本化的成果引用和可持久化数据。大块模型由 Mining 快照及 chunk reader 分页访问，不复制整个项目到每次工具调用。

用户算法可以有两种产出：纯计算报告或几何成果；也可以生成待审查的 Mining 编辑增量。不能预设“用户算法都属于写入”，也不能让算法直接绕过 Mining 的修订检查。

05

从任务到可复用插件

任务编排记录的是可重放的依赖和输入版本，不只是一串工具调用。文档提供标准、约定和证据；Mining 快照提供可计算的当前状态。

建立工作空间

登记测量数据、文档、坐标系、单位与来源；提取文档信息并保留引用。经核对的通用操作说明可形成 Skill。

创建 Mining 数据

导入或构造项目资源，校验对象、几何、属性和坐标；固定输入项目 ID 与 revision。

发现和排程

依据目标、约定、数据类型和前置条件选工作流与算法，形成有依赖的步骤图。长任务可交给 Harness jobs。

执行与审查

运行算法，保存参数、代码/包版本、诊断、产物和数据来源。设计写入先形成候选成果或 delta，再经修订检查提交。

沉淀缺失能力

找不到插件时，先生成一次性程序并用真实样例验收。确认可复用后补齐契约、测试和版本，包装成工作空间插件；需要时提升到个人或团队包库。

“插件开发模式”直接走同一套契约与测试，但以开发可复用包为任务目标。一次性程序通过验收并不意味着自动获得平台级信任或全局安装。

06

与当前打开的另一份方案对比

仅比较关键架构判断。另一份方案的文字与页面样式未用作本页内容或模板；这里把有价值的共同点和需要调整的取舍公开列出。

议题另一份方案本方案的决策与理由
能力包与 Harness 包严格的“两个包世界”，插件只做三项翻译。同意分层，放宽插件职责。平台还需要工作空间、Mining 数据、任务、成果等长期服务与领域工作流；它们不是简单的 schema 翻译。
插件类型主要按 view、tool、chrome、profile 分类。增加服务与工作流。这是平台业务职责分类；实际 Cordis 装载仍使用 Harness 原有扩展点。
用户代码用户代码不能成为 Harness 插件，默认作为沙箱进程或数据。按信任与发布阶段区分。未审查算法默认独立运行；用户明确开发并确认的插件可以经 profile 安装，接受与其他进程内插件相同的信任边界。
算法工具数量检索 + 调用两个通用工具，避免每个算法占一个工具。基本同意。另加完整契约查看与成果审查入口；高频且语义稳定的操作仍可保留独立工具，例如现有 Import。
用户算法定位主要落在写入面，产出 Mining delta；recipe 是优先形态。同时支持计算与写入。地质分析、量测和优化常先产生报告或独立几何；只有发布到项目时才形成 delta。配方适合组合既有能力，不能替代新算法。
常驻运行时较早建设按会话和工作区的常驻运行时以保留原生句柄。按实测需求引入。首期用作业内 Python 任务串联原生对象，跨任务交付用成果引用；当跨调用句柄复用确有收益时再设计常驻服务与生命周期。
工作空间目录以 .dsh/iam 保存用户算法和配方，并单设 profile bundle。按归属拆分。.dsh/skills 用于 Harness 原生 Skill；.iax/ 保存 IAX 算法、插件源码和任务记录。profile 负责启用插件；装配 bundle 可在安装痛点明确后添加。
07

实施顺序与验收

阶段交付验收信号
第一阶段工作空间索引、Mining 读写服务、统一算法注册表与 AlgorithmBridgeheadless profile 能基于真实 Mining 快照发现、验证并调用内置算法；结果有版本和来源。
第二阶段候选成果、修订检查提交、任务记录与步骤依赖一项真实设计任务从输入 revision 到候选 delta、审查和新 revision 可追溯。
第三阶段文档检索、Skill 形成、用户算法提供者和插件提升工作空间算法可发现并运行；缺失能力从一次性程序经测试提升为固定版本插件。
按需扩展常驻计算服务、个人/团队包库、更多领域工作流以跨任务性能、多人复用和实际业务验收数据决定投入。

现阶段不需要修改 CoreEngine、GeomAlg、Drawing 或 Mining 的所有权边界。IAM 适配下层能力；Mining 的项目修订仍由其数据库负责。
